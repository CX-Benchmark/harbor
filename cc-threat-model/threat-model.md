# Threat model — Harbor (github.com/cx-benchmark/harbor, main @ d822d80, VERSION v2.17.0)

Reviewed whole at this commit: the model on file recorded no commit to diff from. "Out of view" = not in this repository or not opened; "not verified" = read but not confirmed. No statements from the project's members were supplied; every attributed statement below is repository text.

## system

Harbor is a self-hosted OCI registry: it stores and serves container images, Helm charts and other OCI artifacts and adds projects, RBAC, robot accounts, replication, proxy cache, vulnerability scanning, signature/SBOM accessories, webhooks, quotas, retention, immutability and P2P preheat on top of the CNCF distribution registry (README.md). README.md says `main` "may be in an unstable or even broken state" and points users to releases.

Components (code read):
- **core** (`src/core/main.go`): one beego process. Global middleware chain in `src/core/middlewares/middlewares.go` `MiddleWares()`: url, mergeslash, regpath (rejects `.`/`..` segments under `/v2/`), trace, metric, requestid, session, csrf, orm, notification, transaction, artifactinfo, security, log, UnauthorizedMiddleware (anonymous fallback), readonly (writes refused in read-only mode except the `readonlySkippers` list). Routes:
  - `src/server/route.go` `registerRoutes`: `/api/version`, beego controllers `/c/login`, `/c/log_out`, `/c/userExists`, `/c/oidc/{login,logout,onboard,callback}`, `/c/authproxy/redirect`, `/api/internal/renameadmin`, `/api/internal/syncquota`, `/service/token`, seven `/service/notifications/...` job-status hooks, error controller.
  - `src/server/registry/route.go`: OCI `/v2/*`, all under `v2auth.Middleware()`; requests are reverse-proxied to the distribution registry with core's registry basic credential injected (`src/server/registry/proxy.go` `basicAuthDirector`, env `REGISTRY_CREDENTIAL_USERNAME/PASSWORD`).
  - `src/server/v2.0/route/route.go`: `/api/v2.0/*` → go-swagger handler generated at build time from `api/v2.0/swagger.yaml` with `tools/swagger/templates` (Makefile `gen_apis`; `src/server/v2.0/restapi` and `models` are not committed); 208 operations implemented in `src/server/v2.0/handler/*.go` (`handler.go` `New`).
  - Listens on 8080, or 8443 with TLS when `INTERNAL_TLS_ENABLED` (`core/main.go`). Optional Prometheus server (`lib/metric/server.go` `ServeProm`, no auth) when `METRIC_ENABLE`; pprof on `PPROF_ADDR` (default `:6060`) only when `PPROF_ENABLED=true` (`src/lib/pprof.go`; called from the core, jobservice, registryctl and exporter mains).
- **jobservice** (`src/jobservice`): gorilla/mux API `/api/v1/{jobs, jobs/{id}, jobs/{id}/log, jobs/{id}/executions, stats, config}` (`src/jobservice/api/router.go`); Redis-backed workers; job implementations in `src/jobservice/job/impl` (replication, gc, notification webhook/slack, purge, scandataexport, systemartifact, gdpr); scan/retention/preheat jobs come from `src/pkg` (not enumerated). Calls back to core `/service/notifications/...` with `JOBSERVICE_SECRET` (`jobservice/hook/hook_client.go`).
- **registryctl** (`src/registryctl`): `GET /api/health`, `DELETE /api/registry/blob/{reference}`, `DELETE /api/registry/{name}/manifests/{reference}` acting directly on registry storage drivers (`handlers/router.go`; azure, filesystem, gcs, inmemory, oss, s3, swift drivers imported in `main.go`).
- **exporter** (`src/cmd/exporter`, `src/pkg/exporter`): Prometheus exporter reading PostgreSQL, Redis and core's API; serves `exporter.metrics_path` and `/` (`pkg/exporter/exporter.go`).
- **standalone DB migrator** (`src/cmd/standalone-db-migrator`) and schema migrations `make/migrations/postgresql/*.sql` (also run by core at start unless `-mode skip-migrate`, `core/main.go`).
- **portal** (`src/portal/src`, Angular 21 + Clarity; `src/portal/app-swagger-ui`) built into an nginx image (`make/photon/portal/Dockerfile`), served per `make/photon/prepare/templates/portal/nginx.conf.jinja` (`/devcenter-api-2.0` → swagger UI).
- Data stores: PostgreSQL via beego ORM (`src/lib/orm`, DAOs in `src/pkg/*/dao`); Redis/Valkey for sessions, cache and the job queue.
- Out of view (other repositories/images): the distribution registry binary (built by `make/photon/registry/builder`), the Trivy adapter, the Helm chart (README.md: goharbor/harbor-helm), Harbor Operator.

Principals the code trusts — security-context generators, tried in order, first non-nil wins (`src/server/middleware/security/security.go` `generators`; a failure to read the auth mode rejects the request):
1. `secret`: `Authorization: Harbor-Secret <s>` (`common/secret/request.go`). Valid only if `s` is a key of `config.SecretStore`, which holds only `JOBSERVICE_SECRET` → user `harbor-jobservice` (`lib/config/systemconfig.go` `initSecretStore`). This "solution user" context's `Can` returns true for every action and resource (`common/security/secret/context.go`); `IsSysAdmin` is false. An invalid secret still yields this (unauthenticated) context and ends the chain.
2. `oidcCli`: OIDC mode, basic auth username + CLI secret, accepted only on `/service/token`, `/v2*`, `POST/GET /api/v2.0/projects`, `GET` systeminfo, `/api/version`, labels, repository and artifact lists, and tag `DELETE` (`oidc_cli.go` `valid`); robot-prefixed names skipped.
3. `v2Token`: `/v2*` bearer JWT issued by `/service/token` (`v2_token.go`).
4. `idToken`: OIDC mode, bearer OIDC ID token on `/api*` and `/service/token` (`idtoken.go`).
5. `authProxy`: `http_auth` mode, `/v2*` only, basic user `tokenreview$<name>` + token checked by the configured TokenReview endpoint; local `SysAdminFlag` cleared, admin only from configured admin groups/usernames (`auth_proxy.go`).
6. `robot`: basic auth whose name starts with the robot prefix (default `robot$`, `lib/config/metadata/metadatalist.go`); PBKDF2 compare, disabled and expiry checks (`robot.go`).
7. `basicAuth`: any basic credentials → `auth.Login` against the configured backend (`basic_auth.go`, `core/auth/authenticator.go`).
8. `session`: beego session value `user` (`session.go`); the stored `models.User`, including `SysAdminFlag`, is the snapshot written at login (`core/api/base.go` `PopulateUserSession`).
9. `proxyCacheSecret`: `Authorization: Proxy-Cache-Secret <s>`, 8 random chars, single-use, 15 s, per process, bound to one repository (`pkg/proxy/secret/manager.go`); core uses it to push proxied content into itself through `CORE_LOCAL_URL` (`controller/proxy/local.go`).
Otherwise anonymous (`unauthorized.go`).

Authentication backends: `db_auth` (default, `AUTH_MODE` in `metadatalist.go`), `ldap_auth`, `oidc_auth`, `uaa_auth`, `http_auth` (`src/core/auth/*`); the super user (id 1) always authenticates against the DB (`authenticator.go` `Login`, `IsSuperUser`).

Build, ship, deploy (own files):
- Go 1.27.3 in a `golang:1.27.3` container (`Makefile` `compile_*`); installers from `make package_offline/package_online`, which copy `make/` into the package and save the images (`Makefile`).
- `.github/workflows/build-package.yml` (push to `main`/`release-*`): builds with `GOBUILDTAGS="include_oss include_gcs" TRIVYFLAG=true EXPORTERFLAG=true`, uploads installers to S3 (`AWS_*` secrets), pushes images to Docker Hub (`DOCKER_HUB_*` secrets).
- `.github/workflows/publish_release.yml` (tags): fetches installers from S3, cosign keyless `sign-blob` (`id-token: write`), publishes images to Docker Hub and GHCR; README.md and `docs/signature-verification.md` document verification.
- Default deployment: Docker Compose rendered by the `prepare` container from `harbor.yml` (`make/install.sh`, `make/prepare`, `make/photon/prepare/templates/docker_compose/docker-compose.yml.jinja`). Only nginx publishes ports (`http_port→8080`, `https_port→8443` when https, `metric.port→9090` when metrics are on) plus `127.0.0.1:1514` for the log container; core, jobservice, registryctl, registry, portal, redis, postgresql, trivy-adapter and exporter are on the internal `harbor` network only. nginx (`templates/nginx/nginx.https.conf.jinja`, `nginx.http.conf.jinja`) proxies `/`→portal and `/c/`, `/api/`, `/v2/`, `/service/`→core, returns 404 for `/v1/` and `/service/notifications`, and redirects port 8080 to https when https is configured; with metrics on, its 9090 server proxies `metric.path` to core, jobservice, registry or exporter by `?comp=`, unauthenticated.

## adversaries

There is no spec-level or application-wide authorization for `/api/v2.0`: `api/v2.0/swagger.yaml` declares `security: [basic: [], {}]` (anonymous allowed) and the generated handler performs no principal check (`tools/swagger/templates/server/configureapi.gotmpl`: `AuthBasic` unset returns no error, `Authorizer` nil). Each operation calls `Require*` helpers itself (`src/server/v2.0/handler/base.go`): `RequireProjectAccess` → `HasProjectPermission` → security context `Can(action, /project/{id}/{resource})`; `RequireSystemAccess` → authenticated + `Can` on the system namespace; `RequireAuthenticated`; `RequireSolutionUserAccess`. A project name that does not resolve becomes project ID 0, whose evaluator is nil, so the check denies (`HasProjectPermission`, `common/rbac/project/evaluator.go` `NewEvaluator`).

### A1 Anonymous network client (reaches nginx)
"Anonymous" below means the handler, the router, the global middleware and the absence of an app-wide default were all read.
- `/api/v2.0` with no check: `GET /ping` (`ping.go`); `GET /health` (component names, statuses and error strings, `health.go`); `GET /icons/{digest}` (`icon.go` → `controller/icon/controller.go` `Get`: icon of any artifact whose Icon field equals the digest, in any project, no project check; blob pulled from the registry, `image.Decode`, resized, re-encoded as PNG); `GET /systeminfo` (auth mode, primary auth mode, self-registration, banner, OIDC provider name, and in `http_auth` mode the auth-proxy endpoint, token-review endpoint, server certificate and verify/skip-search flags; version, external URL, read-only and similar only when authenticated — `systeminfo.go`, `controller/systeminfo/controller.go`); `GET /systeminfo/getcert` (CA download); `GET /retentions/metadatas` (`retention.go`). Outside `/api/v2.0`: `GET /api/version` (`src/server/version.go`).
- Auth-optional: `GET /projects` (anonymous forced to public, `project.go` `ListProjects`); `GET /search` (public projects, `search.go`); `GET /repositories` (public projects, `repository.go` `listAuthorizedProjectIDs`); `POST /users` (`user.go` `requireCreatable`: anonymous only when the auth mode is `db_auth`, `self_registration` is true (default false) and the request carries the `sid` cookie, which also subjects it to CSRF; otherwise system `user:create`).
- Public-project reads through `RequireProjectAccess` with the anonymous RBAC user (`evaluator.go` `NewBuilderForUser`; grants in `common/rbac/project/rbac_util.go` `publicProjectPolicies`: project read, label read/list, repository list/pull, scan read, scanner read, tag list, artifact read/list, artifact-addition read, accessory list): `GET /projects/{project_name_or_id}` and `/summary`, `/projects/{p}/repositories[/{r}]`, `.../artifacts[/{reference}]`, `.../tags`, `.../accessories`, `.../additions/vulnerabilities`, `.../additions/{addition}` (written with the addition's stored Content-Type, `artifact.go` `GetAddition`), `.../scan/{report_id}/log`. `ListLabels`, `GetScannerOfProject` and `HeadProject` call `RequireAuthenticated` first.
- `/v2/*` — `v2auth` (`src/server/middleware/v2auth/auth.go` `check`, `access.go` `accessList`): `/v2/` needs an authenticated context; `/_catalog` needs system `catalog:read`; repository routes need `pull` (GET/HEAD), `push` (POST/PATCH/PUT) or `delete` (DELETE) on the project, plus `pull` on the source of a cross-repository mount; GET/HEAD without an Authorization header get a 401 Bearer challenge; requests with no recognisable access list are rejected. The challenge realm is built from the request `Host` unless it matches `CORE_URL` (`tokenSvcURL`). Routes (`src/server/registry/route.go`): `GET /_catalog`; `GET /*/tags/list` (+repoproxy); `GET|HEAD /*/manifests/:reference` (+repoproxy, content trust, vulnerability prevention); `DELETE` manifests (+quota refresh); `PUT` manifests (+proxy-project upload block, immutable, quota, cosign, subject, blob); `HEAD|GET /*/blobs/:digest`; `POST /*/blobs/uploads`; `PATCH|PUT /*/blobs/uploads/:session_id`; `GET /*/referrers/:reference` (+repoproxy); catch-all `/*` → registry proxy. Anonymous pulls of a public proxy-cache project make core fetch from the upstream with the stored upstream credentials (`server/middleware/repoproxy/proxy.go`, `src/controller/proxy`).
- `GET /service/token` (`core/service/token/token.go`, `creator.go`): unauthenticated with no `scope` → 401; otherwise a token whose actions are filtered per scope by the caller's `Can` (`repositoryFilter`; `registry:catalog` only for sysadmins; unknown types emptied). Anonymous callers get `pull` on public projects.
- `/c/*` (CSRF, see assets): `POST /c/login` (`core/controllers/base.go` `Login`; in OIDC mode a principal that is unknown or OIDC-onboarded gets a 403 redirect JSON instead of a login attempt), `GET /c/log_out`, `POST /c/userExists` (412 unless self-registration is on or the caller is sysadmin), `/c/oidc/login` (`redirect_url` must pass `utils.IsLocalPath`), `/c/oidc/callback` (state from session, PKCE, code exchange, ID-token verification; `oidc_auto_onboard` default false), `POST /c/oidc/onboard` (needs the session's pending user info), `/c/authproxy/redirect` (http_auth only; reviews `token`, logs the user in, then 301-redirects to the `postURI` query value as given — `authproxy_redirect.go`).
- `/service/notifications/*`: `IsSolutionUser` required (`src/server/handler/job_status_hook.go`); nginx returns 404 for them, core's own port is reachable from the internal network.
- `/api/internal/renameadmin`, `/api/internal/syncquota`: `InternalAPI.Prepare` writes 401/403 for non-sysadmins and returns (`core/api/internal.go`); that the action body is then skipped relies on beego's controller dispatch (dependency, out of view). The same pattern guards the auth-mode checks in `OIDCController.Prepare` and `AuthProxyController.Prepare`.
- Any request carrying Basic credentials runs a backend login (`basic_auth.go`) or a robot DB lookup (`robot.go`). A failed login locks that principal for 1.5 s and sleeps 1.5 s (`core/auth/authenticator.go`, `lock.go`, in-process map); no other rate limiting was found.

### A2 Authenticated user, robot account, other tenant
- Project roles: `projectAdmin`, `maintainer`, `developer`, `guest`, `limitedGuest` (`common/rbac/project/rbac_role.go`) plus custom roles whose permissions load from the DB (`evaluator.go`; role create/update/delete is system-only, `role.go`). Any member gets `self:read` (`rbac_user.go`). A project's creator is inserted as its `projectAdmin` (`pkg/project/dao/dao.go` `Create`).
- Any-authenticated operations (check is `RequireAuthenticated` or equivalent, then filtering or per-object checks): `CreateProject` (unless `project_creation_restriction=adminonly`, default `everyone`; robots must be system-level; `registry_id` (proxy cache) and `storage_limit` admin-only; `UpdateProject` rejects `registry_id` changes — `project.go`), `HeadProject`, `ListAuditLogs`/`ListAuditLogExts` (filtered to member projects with `log:list`, `auditlog.go`), `GetPermissions`, `GetCurrentUserInfo`, `GetCurrentUserPermissions` (scope from the query), `SearchUsers`, `SearchUserGroups`, `ListRole`/`GetRoleByID`, `GetSchedulePaused`, `GetStatistic`, `GetSystemCVEAllowlist`, `ListLabels`, CVE-export execution list/get/download (then `requireProjectsAccess`), `UpdateRobot` (then `requireAccess`), user self-service (`GetUser`, `UpdateUserProfile`, `UpdateUserPassword` on one's own id in db_auth; `SetCliSecret` on one's own id in OIDC mode — `user.go` `matchUserID`).
- Project-scoped operations (≈93 of 208): `RequireProjectAccess` with a per-operation resource/action, then helpers that bind child IDs to the project: `requireRuleAccess` (immutable), `requirePolicyInProject` (webhook), `requireExecutionInProject`/`requireTaskInProject`/`requirePolicyAccess` (preheat), `requirePolicyAccess` (retention, via project metadata `retention_id`), `RequireLabelInProject` (artifact labels), `requireNonProxyCacheProject` (copy, tag). Groups: artifacts/tags/labels/accessories/additions/copy (`artifact.go`), repositories, members, project metadata, immutable rules, preheat policies and executions, project retention, project robots, scan/stop/report log, project scanner selection, webhook policies/jobs/executions/logs, project logs, CVE export. Cross-project object references are the tenant boundary.
- Robots: project robots are created by holders of `robot:create` on the project; human creators pass `validateNoEscalation` (each requested access must be held by the creator), robot creators pass `isValidPermissionScope` (`robot.go`). System robots need system `robot:*`. Evaluation in `common/security/robot/context.go` (system/project split, `filterRobotPolicies`, cover-all `/project/*` mapped to `/project/:id`). Secrets are returned on create and refresh (`RefreshSec`).
- Registry tokens: the v2token access map is keyed by the project name in the token (`common/security/v2token/context.go`); tokens lacking `iat` or issued before the project's creation are rejected (`v2_token.go` `tokenIssuedAfterProjectCreation`).
- Group/admin mapping: OIDC groups from token/userinfo are auto-created as user groups and the admin-group claim sets `AdminRoleInAuth` (`pkg/oidc/helper.go` `InjectGroupsToUser`); LDAP admin group and auth-proxy admin lists do the same (`core/auth/ldap/ldap.go`, `pkg/authproxy/http.go`).

### A3 Project admin abusing project features
- Under the defaults any authenticated local user can create a project and so hold `projectAdmin` (A2).
- Webhooks: `/projects/{p}/webhook/policies` create/update/delete (built-in role `projectAdmin` only, `rbac_role.go`). Targets are validated by `validateTargetHost` → `common/http.ValidateNetworkTarget` (`webhook.go`); delivery uses jobservice clients wrapped with `WithEgressGuard` (dial-time address check, proxied-target check) and `blockRedirect` (`jobservice/job/impl/notification/http_helper.go`); a policy's `skip_cert_verify` selects the insecure client (`webhook_job.go`, `slack_job.go`). With `HARBOR_WEBHOOK_EGRESS_POLICY` unset the level is `allow_all` and no checks run (`src/common/http/private_network.go` `parseEgressLevel`); `block_restricted`/`public_only` are opt-in; an invalid value falls back to `public_only`.
- Also: member management, project robots, retention and immutability rules, preheat policies (instances are system-made), project metadata switching content trust, vulnerability prevention, CVE allowlist, public visibility.

### A4 Malicious content author (push access to some project, including one they created)
Core parses pushed artifacts on push and read (`src/controller/artifact/processor/*`): Helm charts via `helm.sh/helm/v3` `loader.LoadArchive` after `io.ReadAll` of the blob (`processor/chart/chart.go`, `pkg/chart/operator.go`, dependency YAML); CNAI model tars with size limits (`processor/cnai/parser/util.go`); annotation icons (1 MiB `LimitReader`, `annotation/v1alpha1.go`); wasm, cnab, sbom, image manifests and indexes; accessories (`pkg/accessory`). The portal renders README/values/license through `ngx-markdown` into `[innerHTML]` (`artifact-additions/summary`, `values`, `license`, `artifact-info` components). Policy interplay: `SkipPolicyChecking` lets scanner-pull v2tokens bypass and treats an artifact whose first accessory is a cosign/notation signature as signed (`server/middleware/util/util.go`); with `CONTENT_TRUST_LEGACY_SIGNER_PULL_ENABLED` unset (default true) a push-capable v2token whose User-Agent contains `cosign` or `notation` may pull unsigned manifests in content-trust projects (`LegacySignerBootstrapPull`, `contenttrust/contentrust.go`).

### A5 Malicious or compromised remote service
- Replication remote registries (15 adapters in `src/pkg/reg/adapter/*`) and proxy-cache upstreams (`src/controller/proxy`, `server/middleware/repoproxy`): manifests, blobs, tag lists and referrers flow into local storage and are served again.
- Scanners (`src/pkg/scan/rest/v1` client; reports in `pkg/scan/report`, `vuln`, `sbom`) drive vulnerability prevention and portal display. Per scan, core creates a non-expiring project robot named `<ROBOT_SCANNER_NAME_PREFIX>-<scanner>-<uuid>` with the scan handler's required permissions, passes it with its secret in job parameters (through Redis to jobservice and on to the scanner) and deletes it in the task callback (`controller/scan/base_controller.go` `makeRobotAccount`, `callback.go`); the prefix is 8 random chars from `prepare/utils/core.py`.
- OIDC provider (`pkg/oidc`: claims set username, groups, admin), LDAP (`pkg/ldap`), UAA (`common/utils/uaa`), auth-proxy TokenReview (`pkg/authproxy`), P2P providers Dragonfly/Kraken (`pkg/p2p/preheat/provider`), webhook receivers (bodies drained, never surfaced — `drainBody`), syslog audit forwarder target (`pkg/audit/forward.go`).
- Who points Harbor at them: registries, scanners, preheat instances and auth/OIDC/LDAP settings are system-level (`RequireSystemAccess` in `registry.go`, `scanner.go`, `preheat.go`, `config.go`, `oidc.go` `PingOIDC`, `ldap.go` `PingLdap`); system robots can be granted those system resources (system scope in `common/rbac/const.go`). The egress guard covers only the notification clients (the only call sites of `WithEgressGuard`/`ValidateNetworkTarget`).

### A6 Peer on the internal network (any container on `harbor`, or anything reaching internal ports)
- jobservice: every route except a request URL exactly `/api/v1/stats` requires `Harbor-Secret <CORE_SECRET>`, compared in constant time, empty rejected (`jobservice/api/authenticator.go`, `router.go` `ServeHTTP`); `GET /api/v1/config` returns the Redis pool config. mTLS only with internal TLS plus the verify-client env (`api/server.go`).
- registryctl: every route except `/api/health` requires `Harbor-Secret` equal to `JOBSERVICE_SECRET`; empty configured secrets are dropped and an empty set denies all (`registryctl/auth/secret.go`, `handlers/handler.go`).
- core reached directly (bypassing nginx): `/service/notifications/*` and the solution-user surface — `GetInternalconfig` and `GetConfigurations` return `AllConfigs` to a solution user (`config.go`) — with `JOBSERVICE_SECRET`.
- Bundled Valkey: `protected-mode no`, no `requirepass` (`make/photon/valkey/redis.conf`); holds sessions (gob), cache (msgpack) and the job queue. Bundled PostgreSQL: password from `harbor.yml` (`root123` in the template), `sslmode=disable` (`prepare/utils/configs.py`). Registry: htpasswd basic auth with `REGISTRY_CREDENTIAL` (`templates/registry/config.yml.jinja`). Component traffic is plain HTTP unless `internal_tls` is enabled (commented out in `make/harbor.yml.tmpl`).

### A7 System administrator
Trusted operator role. Configures every outbound endpoint in A5 (not egress-guarded), auth backends, CVE allowlists, GC, quotas, replication. System-level groups (`RequireSystemAccess`): registries (+ping/info), replication policies/executions/logs/adapters, scanners (+ping/metadata/default), preheat instances/providers/ping, GC, audit purge, scan-all, quotas, user list/sysadmin/delete, user groups, LDAP ping/search/import, configurations GET/PUT, system CVE allowlist PUT, OIDC ping, jobservice pools/workers/queues/jobs/logs, schedules, security hub, system volumes, audit event types, roles, system robots, system retention. `SetUserSysAdmin` also requires `IsSysAdmin`, which robots never have.

Entry points not listed one by one: ≈93 project-scoped and ≈80 system-level `/api/v2.0` operations (approximate scripted count over handler bodies), registered in `api/v2.0/swagger.yaml` and implemented in `src/server/v2.0/handler/*.go`; each one's gate is the first `Require*` call in its function. All core, `/v2`, jobservice, registryctl and exporter routes are covered above.

## assets

- **Artifact integrity and policy state** (registry storage + DB): pushes gated by `v2auth` push, then route middleware in `src/server/registry/route.go` — `repoproxy.DisableBlobAndManifestUploadMiddleware` (no pushes into proxy projects), `immutable`, `quota`, `cosign.SignatureMiddleware`, `subject`, `blob`; pulls gated by `contenttrust.ContentTrust` and `vulnerable.Middleware` per project metadata. Storage deletes outside core only through registryctl with `JOBSERVICE_SECRET`. Proxy-cache writes use a Proxy-Cache-Secret that permits only pull/push/delete on that repository's project (`common/security/proxycachesecret/context.go`).
- **Private project confidentiality**: artifacts, additions (README, values, SBOM, build history), scan reports, audit logs, member and robot lists, webhook payload logs — `RequireProjectAccess`, `v2auth`, the `/service/token` filter.
- **Keys and secrets** (kinds and locations only):
  - Registry-token RSA private key at `TOKEN_PRIVATE_KEY_PATH` (prepare generates `<data_volume>/secret/core/private_key.pem`, `prepare/utils/cert.py`); holding it means minting `/v2` access. Parsing accepts only RS256 (`pkg/token/token.go` `WithValidMethods`; `options.go` RSA-only).
  - Secret key file `KEY_PATH` (16 chars, `<data_volume>/secret/keys/secretkey`, mounted at `/etc/core/key`): AES-CFB `ReversibleEncrypt` without an integrity tag, for stored remote-registry and scanner credentials, OIDC tokens and CLI secrets, config passwords (`common/utils/encrypt.go`, `lib/config/systemconfig.go` `EncryptSecret`); values without the `<enc-v1>` header are read as plaintext (`DecryptSecret`).
  - `CORE_SECRET` and `JOBSERVICE_SECRET` (16 random chars), `REGISTRY_CREDENTIAL_PASSWORD` (32), `CSRF_KEY` (32), generated by `prepare/utils/configs.py`/`core.py` into `common/config/*/env` files. `JOBSERVICE_SECRET` yields core's all-permitting solution-user context.
  - User password and robot secret hashes: PBKDF2 (`common/utils/encrypt.go` `Encrypt`, `pbkdf2Params`); robots are verified with the `sha256` legacy-iteration variant (`robot.go`).
  - Sessions in Redis, cookie `sid` (`lib/config/config.go`), `SESSION_TIMEOUT` default 60 min.
  - Third-party credentials in configuration: LDAP bind password, OIDC client secret, UAA client secret, auth-proxy settings.
- **Admin privilege**: `SysAdminFlag` (DB) and `AdminRoleInAuth` (OIDC/LDAP admin group, auth-proxy admin lists).
- **Audit trail**: log middleware runs after security (`middlewares.go`); DB audit tables, optional TCP syslog forwarding `AUDIT_LOG_FORWARD_ENDPOINT` (`pkg/audit/forward.go`), `SKIP_LOG_AUDIT_DATABASE` (`core/main.go` `initSkipAuditDBbyEnv`); purge and GDPR masking jobs.
- **Availability**: DB connection pool (ping skips ORM/security; the transaction middleware is skipped for reads, blob uploads and token POSTs — `middlewares.go`), Redis, job queue, request sizes (beego `MaxMemory`/`MaxUploadSize` default 128 GiB, `common/const.go`; nginx `client_max_body_size 0`).
- **Release integrity**: cosign-signed installers, Docker Hub/GHCR images, CI secrets (`DOCKER_HUB_*`, `AWS_*`, `GITHUB_TOKEN`, `CODECOV_TOKEN`, `SLACK_WEBHOOK_URL`).

Trust boundaries and where they are enforced:
- Browser ↔ core: CSRF by gorilla/csrf v1.7.2 (pinned in `go.mod`) in `server/middleware/csrf/csrf.go` — header `X-Harbor-CSRF-Token`, SameSite=Strict, Secure unless `EXT_ENDPOINT` starts with `http://`; skipped for `/v2/`, `/api/`, `/service/` unless the request carries the `sid` cookie (`csrfSkipper`, `session/session.go`), applied to every `/c/*` request; gorilla/csrf itself exempts GET/HEAD/OPTIONS/TRACE (dependency behaviour, out of view), so `GET /c/log_out` and the `/c/oidc` GETs are not token-checked. A `CSRF_KEY` that is set but not 32 chars makes every non-skipped request fail. nginx adds `X-Frame-Options DENY` and CSP `frame-ancestors 'none'` (both templates), HSTS and HttpOnly/Secure cookie rewriting (https template).
- User ↔ project: RBAC evaluators (`common/rbac/project`, `pkg/permission/evaluator`; casbin v3 with the custom `keyMatch2` in `pkg/permission/evaluator/rbac/casbin_match.go`).
- core ↔ jobservice ↔ registryctl: the shared secrets above. core ↔ distribution: basic credential; the registry is not exposed.
- Harbor ↔ external services: TLS verification per setting — LDAP verify default true, OIDC verify default true, UAA verify default false, auth-proxy verify default true (`metadatalist.go`); per-registry `insecure`, scanner `skipCertVerify` (`pkg/scan/rest/v1/client.go`), preheat `insecure` (`pkg/p2p/preheat/provider/client/http_client.go`).
- Webhook egress: `common/http/private_network.go` as in A3.

## out-of-scope
